# 데이터 모델

> 프로토타입(`src/data/*`, `src/store/*`) 기준. 백엔드 스키마 설계 참고용 타입/제약.

## 1. Reservation (예약) — 핵심 엔티티

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `reservationNo` | string | ✔ | 노출용 예약번호 `RSV-YYYYMMDD-####` |
| `status` | enum | ✔ | `BOOKED` \| `COMPLETED` \| `CANCELLED` |
| `transactionType` | enum | ✔ | `BUY`(매입·외화→원화, 기본) \| `SELL`(매각·원화→외화) — 금액 단계 방향 토글로 선택 |
| `branchId` | FK→Branch | ✔ | 수령 지점 |
| `currency` | string(3) | ✔ | ISO 4217 |
| `rateMode` | enum | ✔ | `BOARD`(환율 미고정·수령일 전광판) \| `FIXED`(예약시점 고정) — 현재 웹 예약은 `BOARD` |
| `coupon` | boolean | ✔ | 회원가입 쿠폰 적용(수령일 전광판보다 우대) 여부 |
| `rate` | decimal(18,4)\|null | | `FIXED`면 예약시점 픽스값, `BOARD`면 **null**(수령일 정산) |
| `foreignAmount` | decimal(18,2) | ✔ | 외화 금액 |
| `krwAmount` | bigint\|null | | `FIXED`면 `round(foreignAmount*rate)`, `BOARD`면 null(수령일 확정) |
| `appliedRate` / `appliedKrwAmount` | decimal / bigint | | 거래완료(POS) 시 실제 적용환율·최종원화 기록 |
| `customerName` | string | ✔ | 예약자명(여권 영문, 대문자) |
| `email` | string | ✔ | 이메일(형식검증 + OTP 수신확인, 본인인증 아님) |
| `pickupDate` / `pickupTime` | date / HH:mm | ✔ | 수령 예정일·시간 |
| `createdAt` / `processedAt` | datetime | ✔/ | 신청 / 완료 일시 |
| `idVerified` | boolean | ✔ | 현장 신분증 대조 완료(기존 POS 흐름, 시뮬레이션) |
| `reminderStatus` | enum | ✔ | `NONE` \| `CONFIRMED` \| `NO_RESPONSE` |
| `cancelReason` | enum\|null | | `AUTO`(노쇼) \| `CUSTOMER` \| null |

**규칙**
- **환율 미고정(`BOARD`)**: 예약 시 환율을 확정하지 않고 `rate=null`. **수령일 지점 전광판(외국인 웹사이트 매입) 환율**로 POS에서 정산.
- **쿠폰 우대**: `coupon=true`(회원가입 지급)면 수령일 전광판 환율보다 우대(`WEB_COUPON_BONUS`, 데모 +0.8%).
- (레거시 `FIXED`) 예약시점 픽스 건은 거래완료 시 예약환율 vs 오늘환율 중 유리한 쪽 적용(베스트레이트). 시드 데이터에만 존재.
- 방향은 `BUY`(외화→원화)·`SELL`(원화→외화) 양방향 → 고객 화면 금액 단계에서 토글로 선택.
- 노쇼: `cancelReason='AUTO'` 카운트(`countNoShow`)는 안내·통계용. **정책상 신규예약 차단 없음** — 프로토타입도 차단 없이 안내 문구만 노출.
- 인덱스 제안: `UNIQUE(reservationNo)`, `INDEX(email)`, `INDEX(branchId,pickupDate,status)`, `INDEX(status,pickupDate)`.

## 2. Branch (지점)

`id` · `name{ko,en}` · `address{ko,en}` · `leadTimeDays` · `currencies: [통화코드]` · `lat,lng`(거리계산·지도).
`currencies` = 취급통화 코드 목록. **금액 한도(최소·최대·신청단위) 없음.** 준비일수(leadTime) 제한 없음(수령 범위 최대 2주). *(프로토타입 목값은 실제와 다를 수 있음)*

## 3. Rate (환율)

프로토타입 목환율(`src/data/rates.js`)의 `getDisplayRates().base`가 **전광판(외국인 웹사이트 매입) 환율** 역할. 백엔드: `currency · boardRate · effectiveAt`. 웹 예약은 환율을 픽스하지 않고(`BOARD`), 수령일 전광판 환율로 POS에서 정산하며 쿠폰 시 `WEB_COUPON_BONUS`만큼 우대.

## 4. 통화 마스터 (CEMS)

- 통화 마스터 18종: `CURRENCY_ORDER` (+ `CURRENCY_META` 국기·명칭, `MOCK_RATES`).
- 금액 한도(최소·최대·신청단위) 관리는 제거됨.

## 5. Enum
```
ReservationStatus = BOOKED | COMPLETED | CANCELLED
TransactionType   = BUY (외화→원화·매입, 기본) | SELL (원화→외화·매각) — 웹 양방향 지원
RateMode          = BOARD (환율 미고정·수령일 전광판) | FIXED (예약시점 고정, 레거시/시드)
ReminderStatus    = NONE | CONFIRMED | NO_RESPONSE
```

## 6. Out of Scope / 변경 이력
- **회원(User)**: 기존 "없음(확정)" → 현재 **선택적 회원가입**(쿠폰 전용, 이름·이메일+인증). 예약에는 불필요, 프로토타입 시뮬레이션(실제 계정 미생성).
- Payment/PG(무결제·현장결제), 온라인 신분증 업로드: 범위 밖. 노쇼 제재·우대율·취소 컷오프: **없음으로 확정**(07_정책 참고).
