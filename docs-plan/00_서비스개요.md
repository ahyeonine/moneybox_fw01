# 서비스 개요 (전체 정리)

> 머니박스 외국인 환전예약 서비스의 **전체 그림**을 한 문서로 정리한 것. 세부는 각 문서로 연결한다.
> IA `01_IA.md` · 구조도 `02_구조도.mermaid` · 플로우 `03_플로우.mermaid` · API `04_API.md` · 데이터 `05_데이터모델.md` · 상태 `06_상태도.mermaid` · 정책 `07_정책.md`

---

## 1. 한 줄 정의

외국인(인바운드) 고객이 **온라인으로 환전을 예약(무결제)** 하고, 지정 지점을 방문해 **신분증 확인 후 현장에서 전액 결제·수령**하는 서비스. 예약 시점 환율을 픽스하되, 방문일 환율이 더 좋으면 그날 환율을 적용하는 **베스트레이트 보장**이 핵심 약속이다.

- **거래 방향**: 원화 살 때(외화 → 원화, 매입)만. 매각(원화 → 외화)은 미지원.
- **결제/회원**: 무결제 예약 + 현장 전액결제. 로그인·회원가입 없이 예약 가능(회원가입은 쿠폰용 선택).
- **본인확인**: 온라인 본인인증 없음. 이메일 OTP는 "수신 가능한 주소인지"만 확인. 신분증 대조는 수령 시 지점(POS)에서.
- **프로토타입**: 백엔드 없음(목데이터 + 프론트 상태). React + Vite, GitHub Pages 배포.

## 2. 사용자와 서피스

서로 다른 사용자용 시스템을 데모 편의상 한 앱의 상단 탭으로 묶었다.

| 서피스 | 경로 | 사용자 | 한 줄 |
|---|---|---|---|
| **외국인 웹사이트 V1** | `/site` | 인바운드 고객 | 대표 고객 사이트. **지점 먼저 → 신청** |
| **외국인 사이트 2안 V2** | `/site2` | 인바운드 고객 | WOWPASS풍. **금액 먼저 → 지점 선택**(검색·지도) |
| **CEMS (지점 어드민)** | `/cems` | 본사/지점 운영자 | 예약·환율·한도 관리. **각 지점이 로그인해 사용** |
| **POS** | `/pos` | 지점 직원 | 예약 검색 → 거래처리(베스트레이트 정산) |
| **이메일** | `/email` | 운영 | 예약확인·리마인더·OTP 발송 이력/미리보기 |
| **기획문서** | `/docs` | 내부 | 이 문서 뷰어(`docs-plan/`) |

> V1과 V2는 **같은 예약 엔진을 공유**한다. 입구(플로우 순서)만 다르고, 최종적으로 동일한 V1 신청 단계로 합류한다.

## 3. 핵심 시나리오 (엔드투엔드)

고객 예약부터 지점 수령까지, 시스템이 어떻게 이어지는지:

```
[고객] 웹(V1 또는 V2)에서 예약
   → 지점·통화·금액·수령일 선택, "신청하기" 클릭 시점에 환율 픽스
   → 이름·이메일(OTP 수신확인) 입력 → 약관 동의 → 예약 완료(RSV 번호 발급)
        │
        ▼
[운영] CEMS · 외국인 환전예약관리에 예약 표시
   → (리마인더 발송) 고객 응답에 따라: 방문예정 확인=유지·재고차감 / 방문안함=즉시취소 / 무응답=수령기한 대기
        │
        ▼
[지점] 고객 방문 → POS에서 예약 검색 → 신분증(여권) 대조
   → 베스트레이트 정산(예약환율 vs 오늘환율 → 유리한 쪽) → 현장 결제 → 거래완료(COMPLETED)
```

- **웹 → CEMS**: 예약 생성 시 CEMS 예약관리에 즉시 반영.
- **CEMS ↔ POS**: 같은 예약 레코드를 공유. POS 거래완료가 예약 상태를 COMPLETED로 전이.
- **자동취소**: 수령기한(수령예정일 당일 KST 자정) 경과 & 미방문 → 자동취소(`AUTO`). 프로토타입은 SimBar "하루 넘기기"로 시연.
- 상세 상태 전이는 `06_상태도.mermaid`, 화면 흐름은 `03_플로우.mermaid`.

## 4. 서피스별 상세

### V1 · 외국인 웹사이트 (`/site`)
- **홈**: 서비스 가치 순환 히어로 + 🛡️ 베스트레이트 보장(손해 없는 환전) + 실시간 기준환율 + 이용방법/혜택/인기지점/FAQ/CTA.
- **예약(`/site/book`)**: 지점 선택 → 신청(통화·금액·수령일) → 예약자 정보(이름·이메일 OTP) → 최종확인 → 동의 → 완료. **원화 살 때만**. 상단 환율보장 쿠폰 배너 → 선택적 회원가입(예약에는 불필요).
- **예약조회(`/site/lookup`)**: 예약번호+이메일 → 변경/취소/방문예정확인.
- 부가: 지점정보·무인환전기(머니24h)·회사소개·eSIM.

### V2 · 외국인 사이트 2안 (`/site2`)
- 단일 페이지 2단계: **① 금액 입력**(통화·금액 → 예상 원화) → **② 지점 선택**.
- 지점 선택 = 위치 **검색(OpenStreetMap Nominatim)** + **내 위치로 찾기(Geolocation)** + 인기 위치 + 전체 지점 → **Leaflet 지도** + 거리순 추천.
- "예약" → V1 예약 플로우로 **지점·통화·금액 전달**해 신청 단계 진입.

### CEMS · 지점 어드민 (`/cems`)
- 각 지점이 로그인해 자기 지점을 운영하는 어드민(프로토타입은 로그인 지점 1곳을 대표).
- **예약관리**: 외국인 환전예약 리스트(필터·페이지네이션) / 본사 예약관리.
- **환율관리**: 통화·채널별 환율. 외국인 웹사이트는 **매입만** 지원(매각 잠금).
- **한도관리**: 통화별 **최소·신청단위·건당 최대**를 지점이 설정. 최대 상한 **USD 9,999 상당액** 강제.

### POS (`/pos`)
- 예약 검색(이름·수령일·예약번호 끝 4자리) → 결과 → **거래처리**(신분증 대조 → 베스트레이트 정산 → 거래완료).

### 이메일 (`/email`)
- 예약확인·리마인더·OTP 등 발송 이메일 이력과 미리보기(시뮬레이션).

## 5. 확정 정책 (요약)

전문 `07_정책.md`. 프로토타입 동작도 아래에 맞춰 정렬돼 있다.

| 항목 | 정책 |
|---|---|
| 거래 방향 | 원화 살 때(매입)만. 매각 미지원 |
| 환율 | 전 고객 동일 단일 환율. "신청하기" 시점 픽스. 적용환율 = 지점이 CEMS에서 설정한 외국인 매입환율 |
| 베스트레이트 | 정산 시 예약환율 vs 오늘환율 중 고객에게 유리한 쪽 |
| 최소금액 | 기본 **USD 100 상당액**(통화별 환산). 지점이 CEMS에서 조정 |
| 건당 최대 | 지점이 설정, **상한 USD 9,999 상당액**(초과 불가) |
| 신청단위 | 지점이 통화별로 설정(신청 시 단위로 올림) |
| 리드타임 | 제한 없음(예약일 당일부터). 수령 범위 예약일 ~ 최대 2주(14일) |
| 취소 | 컷오프 없음(수령기한 경과 전까지 가능) |
| 리마인더 | 방문안함→즉시취소 / 방문예정→유지·재고차감 / 무응답→수령기한 대기 후 자동취소 |
| 노쇼 | 신규예약 차단 없음(안내 문구만) |
| 회원 | 예약엔 불필요. 선택 회원가입은 환율보장 쿠폰용(이름·이메일 인증) |
| 다국어 | 한·영·중(간체·번체)·일 (현재 구현 ko/en) |

## 6. 데이터·상태 (요약)

- **핵심 엔티티 Reservation**: 예약번호·상태·통화·환율(픽스)·외화금액·원화금액·예약자명·이메일·수령일시·리마인더상태·취소사유. 상세 `05_데이터모델.md`.
- **상태**: `BOOKED → COMPLETED`(지점 거래완료) / `BOOKED → CANCELLED`(고객취소·방문안함응답·자동취소). `BOOKED`에서만 변경·취소 가능. `06_상태도.mermaid`.
- **재고(시재)**: 예약 생성 시 미반영(오버부킹 허용) → 리마인더 방문예정확인 시점에 차감.

## 7. 기술·운영에 필요한 것 (요약)

프로토타입은 목데이터로 동작하지만, 실제 운영에 필요한 요소는 `04_API.md`에 체크리스트로 정리:
백엔드+DB · 환율 피드 · 재고 관리 · 이메일/OTP 발송 · (선택)회원 인증 · 지도/지오코딩 · 자동취소 스케줄러 · CEMS/POS 연동 · 비기능 요건.

- **스택**: React 18 + Vite 5 + React Router 6(HashRouter) · Leaflet(지도) · marked/mermaid(문서 렌더).
- **배포**: `main` push → GitHub Actions → GitHub Pages. Vite `base='/moneybox_fw01/'`.
- **다른 계정으로 이전**: 저장소 최상단 `README.md`의 "다른 계정에서 이어받아 쓰기" 참고(Fork·Pages·base 경로).
