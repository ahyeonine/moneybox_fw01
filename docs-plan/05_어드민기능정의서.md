# 어드민(CEMS) 기능 정의서 — 해외환전예약 서비스

## 요약

**최상위 구조가 5개 탭으로 확장됨**: 외국인 웹사이트 / CEMS / POS / 이메일 / 기획문서

| 화면 | 개발 여부 | 핵심 내용 |
|---|---|---|
| 이메일 관리 (신규 탭) | 신규 | 템플릿 6종 관리(인증번호/신청완료/전일리마인더/자동취소안내/지점취소안내/고객취소안내), 실제 예약데이터 연동, 지점별 지도 포함 |
| 신규예약 리스트 (지점) | 신규/수정 | 시재 준비용 예약 조회 화면 |
| 공통 설정 (한도·리드타임) | 신규 | 정책값 관리 화면 |
| 환율 리스크 관리 (건당 최대금액) | 신규 | 전체 지점 공통 설정 + 원화 기준 일괄등록 (지점 선택 없음) |
| 기존 환율설정 화면 | 수정 | "외국인서비스 환율" 행 추가 |
| 본사관리자 화면 | 신규 | **전 지점 외국인 환전예약 통합 조회**(지점 필터·지점 컬럼 포함). 입금 확인 목적은 없음(예약금 미수취) |

## 1. 신규예약 리스트 (지점, 시재 준비용)

| 항목 | 내용 |
|---|---|
| 목적 | 방문 예정 고객의 통화·금액 파악 (원화 준비) — 외국인 웹사이트는 매입(원화구매)만 영구 지원 |
| 조회 범위 | 본인 지점 예약만 |
| 노출 항목 | 예약번호, 수령예정일, 예약자명(여권 영문명), 이메일, 통화, 거래금액, 예약환율, 원화금액, 상태(예약/완료/취소) |
| 정렬/필터 | 신청일시 최신순(새 예약이 맨 위) 기본. **필터는 기본값으로 "수령예정일 = 오늘"만 적용**, "전체"로 전환하면 날짜 제한 없이 전체 노출 |

**리마인더 응답별 노출 기준** (CEMS·POS 공통)

- 기본 화면 상태: **날짜필터 "오늘" + 토글 "방문확인만 보기"** (둘 다 기본값, CEMS·POS 동일하게 적용)

| 응답 상태 | 기본목록(방문확인만 보기) 노출 | 비고 |
|---|---|---|
| 방문예정 확인 | 노출 | |
| 무응답 (날짜 무관) | 숨김 | 언제든 "전체보기"에서만 노출, 예약번호 직접조회는 항상 가능 |
| 취소/자동취소 | 노출 안 함 | 수령기한(수령예정일 당일) 경과 시 자동취소 |

**기존 CEMS 컬럼 대비 변경**: 성명→예약자명(여권영문명) / 생년월일 삭제 / 휴대전화→이메일 / 입금상태·예약금·종류 삭제

**행 클릭 → 예약 상세 모달 (CEMS)**
- CEMS "외국인 환전예약관리" 리스트에서 거래건(행) 클릭 시 예약 상세 모달을 표시(예약번호/상태/예약자명/이메일/지점/수령일자/통화/예약환율/거래금액/원화금액/신청일시).
- 모달 하단 버튼: **확인**(닫기) + **예약취소**(상태가 `예약`일 때만 노출).
- **예약취소**(지점·직원 취소): 사유 입력·추가 확인 없이 **즉시** 취소 처리.
  - 상태 → `취소`(취소사유=`BRANCH`), 재고 복구(**방문예정확인 건 포함** — 확인 시점에 잡았던 가용시재를 되돌림).
  - **CEMS는 해당 행을 유지**(상태만 `취소`로 표시), **POS 결과 리스트에서는 제외**(취소 건 미노출 규칙).
  - **지점 취소 안내** 이메일 발송(06 템플릿). 고정 사유 문구 `{지점취소사유}` = "지점 사정으로 인해 예약이 취소되었습니다."
- 고객이 직접 취소한 건(예약조회 → 고객 취소완료)과는 **다른 템플릿·사유(CUSTOMER)** 로 구분한다.

**거래 처리(POS)**: 예약번호 조회 → 신분증 OCR 대조(명의 불일치여도 진행) → POS 처리 → 거래완료 (03_예약플로우 문서와 동일 흐름). 신분증 대조/OCR은 **기존 POS 거래 플로우의 일부**이며, 예약 서비스가 그 전에 별도로 신분증을 수집하지는 않는다(온라인 신분증 수집·본인인증 없음).

**POS 환전예약 검색**: 이름 / 수령일 검색(AND) 에 더해 **예약번호 끝 4자리** 검색을 지원. (이메일 검색은 제공하지 않음)
- 예약번호(`RSV-YYYYMMDD-0001`)의 끝자리(`0001`)만 입력하면 **다른 필드·날짜·응답 토글과 무관하게 단독 매칭**(카운터에서 고객이 끝자리만 불러줄 때).
- 끝 4자리가 겹치는 예약(날짜가 다르면 동일 끝자리 가능)은 **여러 건을 리스트로 노출**해 그중 선택한다.
- **거래내용 확인 모달**: 리스트에서 행 선택 시 표시되는 상세(예약번호/상태/예약자명/통화/예약환율/거래금액/원화금액/수령일자/신청일시)에는 **이메일을 노출하지 않는다**(POS 창구에서 불필요).

**베스트레이트(환율 보장) 정산 (POS 거래완료 시점)**
- 거래완료 처리 시점에 **예약환율 vs 그 시점 기준환율(실시간)** 을 비교해 고객에게 더 유리한 쪽으로 최종 정산한다.
- 외국인 웹사이트는 매입(원화구매)만 지원 → 1통화당 원화가 많을수록 유리 → **실제적용환율 = max(예약환율, 오늘환율)**.
- 예약환율/예약 시점 원화금액은 **보존**하고, 실제적용환율·최종원화금액을 **별도 필드**로 기록(04 데이터정의서).
- POS 거래처리 화면에 예약환율·오늘환율(기준)·적용환율(유리한 쪽)·최종 원화금액을 함께 표기해, 어느 환율이 적용됐는지 알 수 있게 한다.

## 2. 공통 설정 (한도·리드타임)

| 설정 항목 | 내용 |
|---|---|
| 환전 한도 | 통화별 최소금액 설정 + 건당 최대금액(전체 지점 공통, 3장 참고) |
| 신청 단위 | 통화별 신청금액 단위 설정 (예: USD 20단위). 외국인 웹사이트에서 단위와 안 맞는 금액 입력 시 상위 단위로 자동 올림. CEMS/POS/이메일/기획문서에는 적용 안 됨(외국인 웹사이트 전용) |
| 리드타임 | 지점/통화별 준비 소요일 설정 (최대 14일(2주)) |
| 이메일당 신청 한도(메모) | **이메일당 1,000 USD 상당액 이하로만 신청 가능** — 정책 메모 단계, 실제 검증 로직 미구현 |

## 3. 환율 리스크 관리 (신규)

배경: 환율은 예약 시점에 픽스됨. 방문 시점까지 환율이 **오르면** 고객은 그냥 워크인으로 현재 시세에 팔면 되므로 지점 손실 없음(예약은 노쇼 처리). 문제는 환율이 **내렸을 때** — 이 경우 고객은 시세보다 유리한 예약 당시 환율을 그대로 적용받아 팔 수 있어, 지점이 시세 대비 비싸게 매입하며 손실을 떠안게 됨. 매입만 지원하는 구조라 이 리스크가 한 방향(환율 하락 시)에 집중되어 있으므로, 건당 손실 규모를 제한하는 상한 설정이 필요함

| 항목 | 내용 |
|---|---|
| 설정 단위 | **전체 지점 공통** (건당 최대금액). ~~지점별~~ 지점 선택 없이 하나의 상한을 전 지점에 공통 적용 |
| 성격 | 고객 예약 자체를 막는 하드리밋 (설정 금액 초과 시 예약 불가) |
| 화면 구조 | 최소금액 / 신청 단위 / 최대금액을 **토글로 전환**하며 관리 (한 화면에 동시 노출 아님) |
| 일괄 등록 (최대금액 토글 시) | **원화 기준 금액 1개 입력** → 로드환율로 환산해 전체 통화 상한 자동 반영 (개별 통화만 이후 수정 가능). 지점 선택 UI 없음 |
| ⚠️ 관리자 설정 상한 | **관리자가 설정할 수 있는 최대금액 자체도 통화별 9,999 USD 상당액까지만 가능** (그 이상 입력/일괄적용 시도 시 에러, 저장 불가) |
| ⚠️ 정책 충돌 | 회의록 [3] "최대금액 제한 없음"과 상충 → 정책회의 재확인 필요 |
| 하향 조정 시 처리 | 관리자가 최대금액을 낮춰도 **이미 생성된 기존 예약에는 소급 적용하지 않음** (그대로 유지, 신규 예약부터 새 상한 적용) |

### 기존 환율설정 화면 수정
기존 화면에 "외국인서비스" 구분 행 추가 (신규 화면 아님). 노출 항목(안): 통화, 로드환율, 적용시각 (회원/비회원 구분 없이 전 고객 동일 환율 — 우대율 구분 없음)

### 매입제외 / 매각제외 체크박스 (통화별)
통화 선택의 목적은 지점의 재고 관리보다는 **환율을 픽스하기 위한 기준**에 가까움 (매입만 지원하므로 어떤 외화가 들어오는지에 따라 적용 환율만 정해지면 됨). 이를 바탕으로 기존 환율설정 화면의 체크박스를 아래처럼 적용:

| 체크박스 | 외국인 웹사이트 행 기본 상태 | 동작 |
|---|---|---|
| 매각제외 | **기본 체크됨 + 수정 불가(딤처리)** | 외국인 웹사이트는 매각(외화구매)을 애초에 지원 안 하므로 항상 고정 |
| 매입제외 | 기본 미체크, 통화별로 관리자가 개별 설정 가능 | **체크한 통화는 고객 신청화면(STEP A 지점선택 이후 통화선택, STEP B)의 통화 목록에서 즉시 제외됨** — 예: 특정 통화 재고 이슈로 임시로 판매 중단할 때 사용 |
| 당일수령불가 | 기존 로직 유지 | 변경 없음 |

### 환율 실시간 연동
- CEMS 환전율관리에서 "외국인 웹사이트" 행의 환율을 변경하면, **외국인 웹사이트 신청화면(STEP B)에 실시간으로 반영**됨
- 환율은 **2분 주기로 자동 갱신**됨 (관리자 수동 변경이 없어도 2분마다 재계산·재조회)

## 4. 본사관리자 화면 (전 지점 통합 조회)
- **전 지점의 외국인 환전예약을 한 화면에서 통합 조회**한다. 지점별 화면(1장, 본인 지점 기준)과 달리 **검색 필터에 "지점" 선택**을 추가하고, 리스트에 **지점 컬럼**을 노출한다.
- 필터: 지점(전체/개별) · 신청기간 · 수령기간 · 상태 · 통화 · 예약자명. 응답범위 토글(방문확인만/전체보기) 동일.
- 행 클릭 → 예약 상세 모달(지점 포함), 상태가 `예약`이면 예약취소(지점·직원 취소) 가능 — 지점별 화면과 동일 동작.
- 입금 확인 목적은 없음(예약금 미수취). 기존 온라인환전 100% 결제형과 달리 본사 입금확인 대상은 아니며, 전 지점 예약 현황 파악 용도.

## 4. 노쇼 제재 (이메일 기준 차단)
- 노쇼 **N회 누적 시, 해당 이메일로는 신규 신청 자체가 차단**됨 (예약 단계에서 이메일 입력 시 즉시 확인)
- N(임계값)은 미정 `[결정 필요]`, 카운트 기준은 "자동취소된 예약" 누적 건수 (고객이 직접 취소한 건은 카운트하지 않음)
- 차단 시 안내 문구: "반복된 노쇼로 인해 서비스 이용이 제한되었습니다" 등

## 5. 최대금액 하향 조정 시 기존 예약 처리
- 관리자가 건당 최대금액(전체 지점 공통)을 낮춰도, **이미 그 이상으로 확정된 기존 예약은 그대로 유지**됨 (소급 취소·조정 없음)
- 새 상한은 그 시점 이후의 **신규 예약에만** 적용

## 6. 재고 반영 시점 및 동시성 처리
- **예약완료(8단계) 시점에는 재고에 반영되지 않음** — 이 시점엔 예약 레코드만 생성되고, 예약시재 반영·가용시재 차감은 일어나지 않음
- **재고(예약시재) 반영·가용시재 차감 시점 = 리마인더에서 고객이 "방문 예정" 응답을 한 시점**
- 따라서 예약 생성 후 리마인더 응답 전까지는 여러 고객이 같은 지점·통화·수령일에 중복으로 예약을 걸어둘 수 있음(재고 경쟁이 이 시점엔 발생하지 않음)
- 재고 경쟁(동시성)은 **리마인더 응답 시점에** 발생 — 여러 명이 동시에 "방문 예정"을 눌러 재고가 부족해지면, **먼저 응답을 확정한 사람이 우선**하여 재고를 차지하고, 나머지는 재고 부족 안내를 받음 (구체적 UX는 `[결정 필요]` — 예: 응답 시점에 재고 부족 알림 후 안내)

## 6-1. 방문예정 확인 후 실제 미방문 (신규 정의)
- **"방문예정 확인"은 노쇼 면제가 아님.** 확인 여부와 무관하게, 수령기한(수령예정일 당일 KST 자정) 경과 시점까지 POS에서 거래완료 처리가 안 됐으면 **동일하게 자동취소** 처리
- 단, **재고 복구 여부는 다름**:
  - 무응답 상태로 자동취소된 경우: 애초에 재고 미반영 → 복구 불필요
  - **방문예정 확인 후 자동취소된 경우: 확인 시점에 반영됐던 예약시재/가용시재를 복구**
- 두 경우 모두 **노쇼 이력(이메일 기준 누적횟수)에는 동일하게 카운트**됨 (확인 후 미방문이 오히려 더 나쁜 케이스이므로 예외 없음)
- 늦게 도착한 요청은 "방금 마감되었습니다" 안내와 함께 지점선택 화면으로 재유도

## 7. 수령기한 판정 기준 시간대
- **한국 표준시(KST) 자정 기준**으로 날짜가 바뀌는 시점에 수령기한 경과로 판정, 무응답 건 자동취소
- 고객의 현지 시간대와 무관하게 지점 운영 기준(KST)으로 통일
