# 예약 플로우 화면 정의서 — 지점수령예약 (8단계)

설계 원칙: 결제 허들이 없으므로 단계를 분리해 예약 진성도를 높인다. 5번(단계 강화 방식)이 확정되면 STEP 8 뒤에 단계가 추가될 수 있음.

> 구현 참고: 아래 8단계는 개념 단위이며, 실제 화면(BookingFlow)은 이를 6개 스테이지로 병합해 구현했다 — **STEP A(지점선택)** + **STEP B(통화·금액·수령일 신청)** 이 1~4단계를 흡수, 이후 정보(5)·최종확인(6)·동의(7)·완료(8). Stepper 라벨도 6개.

| 단계 | 입력/노출 | 검증규칙 | 비고 |
|---|---|---|---|
| 1. 지점선택 | 지점 리스트 | - | 이후 통화·재고 필터링 기준 |
| 2. 통화선택 | 지점 취급 통화만 노출 | - | 통화별 최소금액 수치 `[결정 필요-1]` |
| 3. 금액입력 | 숫자 입력 | 통화별 최소금액 이상 ~ 건당 최대금액(전체 지점 공통) 이하, 초과/미달 시 다음단계 불가 | 환율은 아직 미확정. 최대금액은 전체 지점 공통 설정(05_어드민기능정의서 3장), 수치는 `[결정 필요]`. 참고 메모: 이메일당 1,000 USD 상당액 이하 신청 한도(정책 메모, 검증 미구현) |
| 4. 수령일선택 | 캘린더 | 리드타임 이후 날짜만, 최대 14일(2주) 이내 | 리드타임은 CEMS에서 설정 |
| 5. 예약자정보 | 예약자명(여권영문명), 이메일 → **이메일 OTP 인증(6자리, 5분 유효)** — 본인인증이 아니라 입력 이메일의 수신 가능 여부 확인용 | 이메일 형식 검증, **이메일 기준 누적 노쇼 N회 이상이면 예약 차단**(N값 `[결정 필요]`, 인증 진행 전에 체크), 인증번호 오답 5회 시 재발송 필요, 재발송 쿨다운 30초 | 인증 완료해야 다음 단계 진행 가능. 로그인·회원가입·본인인증 없음, 생년월일·신분증 미수집. 프로토타입은 실제 발송 없이 화면에 데모 코드 노출 |
| 6. 최종확인 | 지점·통화·금액·확정환율·원화금액·수령일 요약 | 재고 소진 여부 참고 확인(소프트 체크, 실제 재고 반영/차감 아님), **이 시점에 환율 픽스** | 수령 시 지점에서 신분증 대조는 하되 예약자명=방문자 명의 동일성은 불요구. 실제 재고 반영은 리마인더 "방문예정" 응답 시점(아래 참고) |
| 7. 정책동의 | **베스트레이트 보장 안내** + 노쇼 안내·개인정보 동의 체크박스 | 전체 동의 필수 | 노쇼 제재는 없음 — 안내성 문구로 작성. 베스트레이트 안내(동의 대상 아님, 안내 배너): "현재 환율이 가장 유리해요. 혹시 방문하시는 날 환율이 더 좋아지면, 그날의 환율로 적용해드립니다." (POS 거래완료 정산과 연동 — 05_어드민기능정의서 참고) |
| 8. 예약완료 | 예약번호 발급, 완료 알림 발송 | - | 단계 강화 옵션 삽입 지점(더블옵트인/캘린더 등록 등) `[결정 필요-5]` |

## 예외 처리
- 금액 미달(3단계) / 선택 가능일 없음(4단계) → 에러 안내
- 재고 소진(6단계) → 마감 안내 후 1단계 재진입
- **동시 예약 충돌**: 예약 생성 시점(1~8단계)에는 재고가 실제로 차감되지 않으므로, 이 구간에서는 여러 명이 같은 지점·통화·수령일에 중복 예약을 걸어도 충돌이 발생하지 않음. **실제 재고 경쟁은 리마인더에서 "방문 예정"을 확정하는 시점에 발생** — 여러 명이 동시에 확정을 시도하면 먼저 확정한 사람이 우선(선착순)하여 재고를 차지하고, 나머지는 재고 부족 안내를 받음. (구현 권장: 서버에서 재고 차감을 원자적 연산으로 처리 — 프로토타입에서는 목데이터 상태값으로 간단히 시뮬레이션해도 무방)
- 중도 이탈 → 임시저장 없음, 재입력
- 취소 요청 → 컷오프 여부 `[결정 필요-8]`에 따라 분기

## 상태값
`예약`(8단계 완료 직후) → `완료`(현장 거래 완료) / `취소`(고객취소·자동취소)

**수령기한** = 수령예정일 당일. 전일 리마인더에 무응답이어도 수령기한 전까지는 취소하지 않음(POS 기본목록엔 숨김, 예약번호 직접조회는 가능). 수령기한 경과 시 자동취소, 명시적 "취소" 응답은 즉시 취소.
