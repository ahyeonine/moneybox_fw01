> 개발에 필요한 세부 규칙·정책·데모 동작을 한 곳에 모은 문서. 개요/IA는 `01_IA.md`, 구조·플로우·상태 다이어그램은 `02~06`, API·데이터는 `04~05` 참고. 값은 프로토타입 목데이터이며 `// TODO`는 실제 정책 확정 필요.

## 0. 기술/배포
- Vite 5 + React 18 + react-router-dom 6(**HashRouter** — GitHub Pages 딥링크/새로고침 404 방지).
- 배포: GitHub Pages, `vite.config.js` `base:'/moneybox_fw01/'`, `.github/workflows/deploy.yml`(수정 금지). URL: `https://ahyeonine.github.io/moneybox_fw01/#/...`
- 상태는 프론트 Context로만 관리(백엔드 없음). 새로고침 시 어드민 설정/시뮬레이션 상태 초기화.
- i18n: `src/i18n/strings.js`(키→{ko,en}), `useI18n().t()`. 한/영 2종, 中·日 확장(키 구조 유지).
- 지도/외부호출(V2)은 **사용자 브라우저에서 OpenStreetMap에 직접 호출**(무료·키 불필요). 빌드/CI 환경에선 외부 타일 차단될 수 있으나 배포 사이트에선 정상.

## 1. V1 예약 플로우 (`/site/book`)
- 단계(STAGES): `branch → apply → info → review → consent → done`.
- **원화 살 때(외화→원화)만 지원**: `transactionType='BUY'` 고정, "환전구분" 미노출. 기준환율은 방향 토글 없이 단일("원화 살 때") 노출(구 외화 살 때/팔 때 탭 제거).
- **환율 픽스**: "신청하기"(apply) 클릭 시점의 환율을 예약에 픽스. 이후 화면은 표시만.
- **금액 자동보정**: 입력 blur/다음 진행 시 단위(unitStep) 올림 → 최대 초과 시 최대 → 최소 미만 시 최소.
- 한도: 통화별 최소(`minAmounts`)·지점별 최대(`getMaxAmount`)·신청단위(`unitAmounts`, 웹에서만 올림). CEMS 한도관리와 실시간 연동.
- 수령일: 리드타임 이후 ~ **최대 2주(14일)**. 시간 슬롯은 지점 영업시간 기준.
- **재고 소진 데모**: `B003(인천공항T1) + VND` 조합은 sold-out 예외 플로우 시연.
- **이메일당 1,000 USD 상당 이하**만 신청 가능(검증 로직 미구현 — 정책 메모).

## 2. 이메일 OTP (예약자정보 단계 · 회원가입 공통)
- 목적: **수신 가능한 이메일인지 확인**(본인인증 아님). 완료해야 다음 단계.
- 정책: 코드 5분 유효(`OTP_TTL`), 재발송 30초 쿨다운, **5회 오답 시 코드 무효화**. 데모는 인증번호를 화면 배너로 표시(실발송 없음).

## 3. 회원가입(선택) — 쿠폰 전용
- 진입: `/site/book` 상단 **"환율 최저가 보장 쿠폰" 배너 → 회원가입 모달**.
- 폼: **이름 + 이메일 + 이메일 인증번호**(위 OTP 규칙 재사용). 이름 입력 + 인증 완료 시 "회원가입하고 쿠폰 받기" 활성.
- **예약에는 회원가입 불필요** — 모달에 "가입 없이 예약 계속" 제공, 가입 시 배너가 "쿠폰 적용됨"으로 전환(세션 기준). 프로토타입 시뮬레이션(실제 계정 미생성).

## 4. 동의 (consent 단계)
- 필수 전체동의 4종: 이용약관 · 개인정보 수집·이용 · 개인정보 제3자 제공(수령 지점 운영사) · 노쇼 안내.
- 수령 시 **신분증(여권) 지참** 안내(최종확인·완료·리마인더 이메일에도 동일). 온라인 신분증 수집/본인인증 없음.

## 5. 베스트레이트 보장
- 안내: 히어로(🛡️ 손해 없는 환전)·신청 화면 강조 박스·쿠폰·동의 단계 배너.
- 정산(POS 거래완료): **예약환율 vs 오늘환율 비교 → 원화구매(BUY)에 유리한(원화 더 많은) 쪽 적용**. 실제적용환율·최종원화금액 별도 기록. → 예약보다 불리하지 않음.

## 6. 예약 상태/자동취소/재고 (요약, 상세는 06_상태도)
- 상태: `BOOKED → COMPLETED`(거래완료, `idVerified` 선행) / `BOOKED → CANCELLED`(고객취소·자동취소). 종료상태 불변.
- **자동취소**: 수령기한(당일 KST 자정) 경과 & `BOOKED` → `CANCELLED(cancelReason=AUTO)`. 리마인더 응답 무관.
- **재고 경쟁은 예약 생성이 아니라 '방문예정 확인' 시점**에 발생: 예약 생성은 재고 미반영(오버부킹 허용), 예약조회의 "방문 예정 확인"에서 `consumeStock`으로 차감. 소진 시 안내(상태 유지).
- 재고 복구: 방문예정확인(차감됨) 후 미방문 자동취소 → 복구. 미응답 자동취소 → 복구 없음.
- **노쇼 차단**: `AUTO` 누적 ≥ `NOSHOW_LIMIT`(현재 2, // TODO)면 예약자정보 단계에서 신규예약 차단(고객취소 제외).
- 데모: SimBar "하루 넘기기" + "자동취소 실행"으로 시간경과 시뮬레이션. 경쟁 데모 `rush@example.com`, 확인후미방문 데모 `visit@example.com`.

## 7. CEMS (어드민)
- **환율관리**(`/cems/settings/rates`): 외국인 웹사이트 채널은 **매입(원화구매)만 영구 지원 → 매각 미지원 잠금(saleNA)**. "외국인 웹사이트" **매입환율 직접 입력 시 신청화면(STEP B) 환율에 실시간 반영**. 매입제외 체크 시 해당 통화가 신청화면 통화선택에서 즉시 제외. 기준율/사실때·파실때는 2분마다 자동 변동.
- **한도관리**(`/cems/settings/limits`): 통화별 최소(전 지점 공통) + 지점별 건당 최대(USD 기준 일괄입력 → 통화별 상당액 자동계산 후 개별수정). **최대금액 하향은 기존 예약 레코드 불변**(신규에만 적용).
- **외국인 환전예약관리**(`/cems/reservations`), 본사 예약관리(`/cems/hq`).

## 8. POS
- `/pos/reservation` 예약검색 → 결과 → `/pos/transaction` 거래처리: **신분증 대조(기존 POS OCR, 시뮬레이션) → 거래완료 → 베스트레이트 정산**. 내국인 탭은 기존 환전예약 사이트로 안내.

## 9. V2 (`/site2`) 세부
- 2단계: 금액 입력 → 지점 선택. 통화 칩 = 지점 취급통화 합집합(막다른 선택 방지).
- 위치 검색: **Nominatim**(`countrycodes=kr`, 디바운스 ~550ms, 실패 시 인기 위치 폴백). "내 위치로 찾기" = `navigator.geolocation`.
- 지도: **Leaflet + OSM 타일**, 마커는 `circleMarker`(번들 아이콘 이슈 회피), 지연 로드·실패 시 무시. 거리 = 하버사인. 통화 취급 지점만 거리순 추천.
- "예약" → `/site/book?branch=&currency=&amount=`로 딥링크(신청 단계 프리필). 데모 완료화면 없음(실제 플로우로 이관).
- 다크 푸터 = OrangeSquare 참고.

## 10. 알림/리마인더 (정책 메모)
- 신청완료 이메일(예약정보·신분증 지참 안내), 수령 전일/당일 리마인더(방문예정 확인 유도), 취소 안내. 문안은 `EmailContext`/이메일 템플릿 기준. 실발송 미구현(데모 발송 이력만).
