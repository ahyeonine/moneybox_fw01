## 1. 개요 (Overview)

**영업일 매일 아침 08:30(KST)**에 주요 통화(**USD, JPY**)의 환율 정보를 한국수출입은행 매매기준율 기준으로 자동 수집하여, 사람이 읽기 좋은 **환율 보고서**를 생성하고 지정된 **Notion**에 자동 기록/발송하는 시스템.

담당자가 매일 수동으로 환율을 확인·정리·공유하던 반복 업무를 완전 자동화하고, 일자별 환율을 Notion에 시계열로 축적한다.

---

## 2. 배경 및 문제 정의 (Background & Problem)

- 환율은 자금·정산·해외거래·가격정책 의사결정에 매일 영향을 주는 핵심 지표다.
- 현재는 담당자가 매일 아침 직접 확인하고 수기로 정리해 공유한다.
- 문제점:
  - **반복 수작업**: 매일 소요, 담당자 부재 시 누락.
  - **일관성 부족**: 확인 시점·출처·포맷이 사람마다 다름.
  - **이력 관리 부재**: 일자별 추세를 남기고 되짚기 어려움.

---

## 3. 목표 (Goals) / 비목표 (Non-Goals)

### 3.1 목표
- G1. **영업일 매일 08:30 KST**에 사람 개입 없이 환율 보고서를 자동 생성·발송한다.
- G2. USD·JPY의 **환율 및 전일 대비 등락**을 한눈에 파악하게 한다.
- G3. Notion에 **일자별 시계열로 축적**하여 이력 조회가 가능하게 한다.
- G4. 데이터 조회 실패 시 **조용히 실패하지 않고** 알림/표기를 남긴다.

### 3.2 비목표 (이번 범위 아님)
- N1. 환율 예측/전망 분석.
- N2. 실시간/틱 스트리밍 (1일 1회 스냅샷).
- N3. 매매·헤지 등 트랜잭션 실행.
- N4. USD·JPY 외 통화 (추후 확장).

## 5. 핵심 요구사항 (Requirements)

### 5.1 데이터 수집
- R1. **영업일** 08:30(KST) 기준 최신 환율을 조회한다.
- R2. **기준 통화: KRW(원화)**. 대상 통화: **USD, JPY(100엔)** *(확정)*.
- R3. **데이터 출처: 한국수출입은행 매매기준율 API** *(확정)*.
  - 조회 항목(일별): 매매기준율, (제공 시) 전신환 매도/매입율.
  - ⚠️ **OHLC 관련**: 한국수출입은행 API는 **일별 단일 기준율**을 제공하며 장중 시가/고가/저가/종가(OHLC)는 제공하지 않는다. 처리 방식은 §10 참조.
- R4. 각 통화별 파생 항목을 계산한다.
  - 현재(당일) 기준율
  - 전일(직전 영업일) 기준율
  - 전일 대비 등락액 / 등락률(%)
- R5. 한국수출입은행 데이터가 미갱신/누락일 경우, 직전 영업일 값 사용 및 그 사실을 표기한다.

### 5.2 보고서 생성
- R6. 보고서 구성.
  - 헤더: `📈 환율 보고서 | YYYY-MM-DD (요일) 08:30 KST 기준`
  - 통화별 라인: `국기 통화 : 기준율 (▲/▼ 등락액, 등락률%)`
  - 등락 방향 시각 표기(▲ 상승 / ▼ 하락 / - 보합)
  - 데이터 기준일 및 출처(한국수출입은행 매매기준율) 명시
- R7. 숫자는 천 단위 구분, 소수 2자리로 통일. JPY는 100엔 기준 표기.

### 5.3 Notion 발송/기록
- R8. 지정된 **Notion 데이터베이스(또는 페이지)**에 당일 보고서를 기록한다. *(대상 위치 → 확정 필요: §10)*
- R9. **권장 구조 — Notion 데이터베이스(시계열):** 매 영업일 1개 행(Row) 추가.
  - 컬럼(예): `기준일(Date)`, `통화(USD/JPY)`, `기준율`, `전일대비`, `등락률%`, `출처`, `기록시각`
  - USD·JPY를 각각의 행으로 적재하여 이력 필터·차트에 활용.
- R10. 보고서 본문(가독형 요약)은 페이지 콘텐츠(콜아웃/표 블록)로도 함께 남길 수 있다.
- R11. 기록 성공/실패를 로그로 남긴다.

### 5.4 스케줄링
- R12. **영업일 매일 08:30 KST**에 자동 실행된다.
- R13. **영업일만 발송** *(확정)*.
  - 토·일 미발송.
  - **대한민국 공휴일 미발송** *(공휴일 판정 방식 → §10)*.

### 5.5 오류 처리
- R14. 데이터 조회 실패 시 재시도(2회, 지수 백오프) 후에도 실패하면, 실패 사실을 Notion(및/또는 알림)에 기록한다("환율 조회 실패 — 수동 확인 필요").
- R15. 부분 실패(USD·JPY 중 일부만 조회) 시, 조회된 통화는 기록하고 실패 통화는 `N/A`로 표기한다.

## 6. 사용자 시나리오 (User Scenario)

> **평일 아침 08:30**, 재무 담당자 A의 Notion `환율 보고` DB에 오늘자 행이 자동 추가된다.
> A는 DB 최신 행에서 USD 1,372.50원(▲4.20, +0.31%), JPY(100엔) 932.40원(▲1.05, +0.11%)을 확인한다. 필요 시 DB를 날짜로 정렬해 최근 추세도 바로 훑는다. 수동 조회·정리는 없다.

## 8. 데이터 소스 (Data Source) — 확정

- **한국수출입은행 현재환율 API** (매매기준율, `deal_bas_r`).
  - 무료, 국내 공신력 있는 일별 매매기준율.
  - 인증키(API Key) 발급 필요.
  - 갱신 특성: **영업일 1회성 일별 값**(주말·공휴일 미갱신). 장중 OHLC 미제공 → §10.
  - 조회 통화: USD, JPY(100). *(JPY는 100엔 단위 표기 유의)*

## 9. 시스템 아키텍처 — 옵션 A (Claude Code Routine) 확정

```
[Claude Routine  (영업일 08:30 KST 트리거)]
        │
        ▼
[영업일/공휴일 판정]  ── 휴일이면 종료(미발송)
        │  (영업일)
        ▼
[한국수출입은행 API 호출]  ──(실패 시 재시도·직전 영업일 폴백)
        │
        ▼
[보고서 생성]  (등락 계산 · 포맷팅)
        │
        ▼
[Notion 기록]  (DB 행 추가 + 요약 블록)  ──실패──▶ [실패 알림/로그]
```

- **트리거:** Claude Code 스케줄 트리거(Routine) — 영업일 08:30 KST.
  - 크론은 UTC 기준이므로 **08:30 KST = 23:30 UTC(전일)**. 요일 시프트 유의.
  - 주말은 크론에서 제외, **공휴일은 세션 로직에서 판정**하여 미발송.
- **데이터 연동:** 한국수출입은행 API (HTTPS).
- **발송:** Notion MCP로 대상 DB에 행 추가/페이지 작성.
- 장점: 별도 서버/인프라 불필요, MCP로 Notion 연동 간단.
- 유의: 트리거 신뢰성·인증(토큰/키) 유지, 실행 로그 확인.

## 10. 확인 필요 사항 (Remaining Decisions)

거의 확정되었고, 착수 전 아래만 정해주시면 됩니다.

1. **OHLC 처리 (중요)** — 한국수출입은행 매매기준율은 일별 단일값이라 진짜 OHLC(시/고/저/종)가 없습니다. 택1:
   - **(권장) A안**: 일별 기준율을 그대로 기록(= 사실상 종가 1개), Notion에 시계열로 축적. 소스 그대로·정확.
   - **B안**: OHLC가 반드시 필요하면 별도 **시장 FX 데이터 소스**(장중 시세)를 추가 도입. (출처·비용·정확도 별도 검토 필요)
2. **Notion 대상 위치** — 기록할 Notion **DB(권장) 또는 페이지**의 링크/ID. (DB면 컬럼 스키마 §5.3 R9로 생성)
3. **공휴일 판정 방식** — (a) 대한민국 공휴일 API/캘린더 연동, (b) 연 1회 수기 공휴일 목록 관리 — 택1.
4. **실패 알림 경로** — 조회/기록 실패 시 어디로 알릴지 (Notion 표기만 / 별도 채널 알림 추가).

## 13. 리스크 (Risks)

- API 갱신 지연/장애 → 재시도 + 직전 영업일 폴백 + 실패 알림.
- OHLC 기대와 소스 특성 불일치 → §10-1에서 사전 합의(권장 A안).
- 크론 UTC↔KST 변환/요일 시프트 오류 → 트리거 검증 및 첫 주 모니터링.
- 공휴일 판정 누락 → 공휴일 소스 이원화 또는 수기 목록 점검.
- Notion 토큰/권한 만료 → 기록 실패 감지 및 알림.
