## 1. 개요 (Overview)

매일 아침 **08:30(KST)**에 주요 통화의 환율 정보를 자동으로 수집하여, 사람이 읽기 좋은 **환율 보고서**를 생성하고 지정된 **Slack 채널**로 자동 발송하는 시스템.

담당자가 매일 수동으로 환율을 확인·정리·공유하던 반복 업무를 완전 자동화하여, 하루를 환율 브리핑으로 시작할 수 있게 한다.

---

## 2. 배경 및 문제 정의 (Background & Problem)

- 환율은 자금·정산·해외거래·가격정책 의사결정에 매일 영향을 주는 핵심 지표다.
- 현재는 담당자가 매일 아침 포털/은행 사이트를 직접 열어 환율을 확인하고, 수기로 정리해 팀에 공유한다.
- 문제점:
  - **반복 수작업**: 매일 5~10분씩 소요, 담당자 부재 시 누락.
  - **일관성 부족**: 확인 시점·출처·포맷이 사람마다 다름.
  - **전일 대비 변화 파악 어려움**: 등락/추세를 매번 눈으로 계산.

---

## 3. 목표 (Goals) / 비목표 (Non-Goals)

### 3.1 목표
- G1. 매일 정해진 시각(08:30 KST)에 **사람 개입 없이** 환율 보고서를 자동 발송한다.
- G2. 주요 통화의 **현재 환율 + 전일 대비 등락**을 한눈에 파악할 수 있게 한다.
- G3. Slack에서 바로 읽기 좋은 **가독성 높은 포맷**으로 제공한다.
- G4. 데이터 조회 실패 시에도 **조용히 실패하지 않고** 알림을 남긴다.

### 3.2 비목표 (이번 범위 아님)
- N1. 환율 예측/전망 등 분석 리포트 (단순 시세 + 등락만 제공).
- N2. 실시간/틱 단위 스트리밍 (1일 1회 스냅샷).
- N3. 매매·헤지 등 트랜잭션 실행.
- N4. 웹 대시보드/DB 축적 (v1은 발송 중심, 이력 저장은 선택 항목).

## 5. 핵심 요구사항 (Requirements)

### 5.1 데이터 수집
- R1. 매일 08:30(KST) 기준 최신 환율을 조회한다.
- R2. **기준 통화: KRW(원화)**. 아래 통화의 원화 환율을 제공한다.
  - **기본 세트(가정):** USD, EUR, JPY(100엔), CNY, GBP  *(→ 확정 필요: §10)*
- R3. 각 통화별로 아래 항목을 수집한다.
  - 현재 환율(매매기준율)
  - 전일(직전 영업일) 환율
  - 전일 대비 등락액 / 등락률(%)
- R4. 데이터 출처는 신뢰 가능한 단일 소스를 우선 사용하고, 실패 시 대체 소스로 폴백한다. *(출처 후보 → §8)*

### 5.2 보고서 생성
- R5. 보고서에는 다음이 포함된다.
  - 헤더: `📈 환율 보고서 | YYYY-MM-DD (요일) 08:30 기준`
  - 통화별 라인: `국기이모지 통화 : 현재환율 (▲/▼ 등락액, 등락률%)`
  - 등락 방향에 따른 시각 표기(▲ 상승/빨강, ▼ 하락/파랑, - 보합)
  - 데이터 기준 시각 및 출처 명시
- R6. 숫자는 천 단위 구분, 소수점 자리수 통일(예: 원화 소수 2자리).

### 5.3 Slack 발송
- R7. 지정된 Slack 채널로 메시지를 발송한다. *(채널 → 확정 필요: §10)*
- R8. Slack **Block Kit**을 사용해 표/구분선으로 가독성을 높인다(단순 텍스트 폴백 지원).
- R9. 발송 성공/실패를 로그로 남긴다.

### 5.4 스케줄링
- R10. 매일 **08:30 KST**에 자동 실행된다.
- R11. **영업일 처리 정책**을 따른다. *(가정: 주말·공휴일에도 발송하되 "직전 영업일 기준"으로 표기 / 또는 주말·공휴일 미발송 → 확정 필요: §10)*

### 5.5 오류 처리
- R12. 데이터 조회 실패 시 재시도(예: 2회, 지수 백오프) 후에도 실패하면, 오류 사실을 Slack에 알린다("환율 조회 실패 — 수동 확인 필요").
- R13. 부분 실패(일부 통화만 조회) 시, 조회된 통화는 발송하고 실패 통화는 `N/A`로 표기한다.

## 8. 데이터 소스 후보 (Data Source Options)

| 후보 | 장점 | 유의점 |
|------|------|--------|
| **한국수출입은행 환율 API** | 국내 공신력 있는 매매기준율, 무료 | 하루 갱신 시점/키 발급 필요, 주말 미갱신 |
| ExchangeRate-API / open.er-api | 무료 티어, 간편 | 원화 기준율과 미세 차이, 갱신주기 확인 필요 |
| Open Exchange Rates | 통화 다양 | 무료 티어 제한 |
| 네이버/한국은행 ECOS | 국내 기준 | 크롤링/키 정책 확인 |

> **권장(가정):** 1차 = 한국수출입은행 API(매매기준율), 폴백 = ExchangeRate-API. *(→ 확정 필요: §10)*

## 9. 시스템 아키텍처 (Architecture Options)

Claude Code로 제작하므로 아래 2가지 구현 방식을 제안한다.

### 옵션 A — Claude Code Routine 기반 (권장, 서버리스)
- Claude Code의 **스케줄 트리거(Routine/Cron)** 로 매일 08:30 세션을 깨운다.
- 세션이 환율 API를 호출 → 보고서 생성 → **Slack MCP**로 발송.
- 장점: 별도 서버/인프라 불필요, MCP로 Slack 연동 간단.
- 유의: 실행 환경 상시성/토큰, 트리거 신뢰성 확인 필요.

### 옵션 B — 독립 스크립트 + 크론 (Python/Node)
- `fetch_rates → build_report → post_to_slack` 3개 모듈로 구성.
- OS 크론/클라우드 스케줄러(예: GitHub Actions `schedule`, cron)로 08:30 실행.
- Slack Incoming Webhook 또는 Bot Token 사용.
- 장점: 이식성·테스트 용이, 이력 축적 확장 쉬움.

```
[Scheduler 08:30 KST]
        │
        ▼
[fetch_rates] ──(1차 API 실패 시)──▶ [fallback API]
        │
        ▼
[build_report]  (등락 계산 · 포맷팅)
        │
        ▼
[post_to_slack] (Block Kit) ──실패──▶ [알림/로그]
```

> **권장:** 빠른 착수는 옵션 A, 장기 운영·확장은 옵션 B. *(→ 확정 필요: §10)*

## 10. 확정 필요 사항 (Open Questions / Decisions)

착수 전 아래 항목의 결정이 필요합니다.

1. **대상 통화**: 기본(USD/EUR/JPY/CNY/GBP)로 확정? 추가/제외?
2. **데이터 출처**: 한국수출입은행 기준율로 확정? (또는 다른 소스)
3. **Slack 채널**: 발송 대상 채널명/ID은? (예: `#환율-보고`)
4. **주말·공휴일 정책**: (a) 매일 발송+직전 영업일 기준 표기, (b) 영업일만 발송 — 택1
5. **구현 방식**: 옵션 A(Claude Routine) vs 옵션 B(독립 스크립트)
6. **이력 저장 여부**: 발송만 할지, DB/시트에 일자별 환율을 축적할지
7. **멘션/알림**: 특정 등락률 이상 시 담당자 멘션 등 임계 알림 필요 여부

## 11. 성공 지표 (Success Metrics)

- M2. **정시성**: 08:30 ± 5분 이내 발송.
- M3. **수작업 제거**: 담당자의 수동 환율 확인/공유 업무 0건.
- M4. **데이터 정확성**: 출처 대비 오차 0(포맷팅/반올림 정책 내).

## 13. 리스크 (Risks)

- 환율 API의 갱신 지연/장애 → 폴백 소스 및 실패 알림으로 대응.
- 주말/공휴일 미갱신 데이터 오해 → "기준 영업일" 명시로 대응.
- Slack 토큰/권한 만료 → 발송 실패 감지 및 알림 필요.
- 스케줄러 미실행(트리거 누락) → 실행 로그/헬스체크로 감지.
