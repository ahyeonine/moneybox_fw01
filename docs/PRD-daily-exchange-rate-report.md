## 1. 개요 (Overview)

**영업일 매일 아침 09:10(KST)**에 주요 통화(**USD/KRW, JPY/KRW**)의 환율 **일봉 OHLC**를 **Twelve Data**에서 수집하여, 사람이 읽기 좋은 **환율 보고서**를 생성하고 지정된 **Notion**에 자동 기록/발송하는 시스템.

- 일봉은 **GMT(UTC) 기준**으로 조회하여 **Investing.com 일봉 차트와 경계를 정합**한다.
- 발송 시각을 09:10 KST로 두어 **직전 거래일의 GMT 일봉이 완성된 뒤** 보고한다(00:00 UTC = 09:00 KST 마감).
- 일자별 환율을 Notion에 **시계열로 축적**하고, 조회·기록 실패 시 **Slackbot으로 알림**한다.

> **발송 시각 변경 사유(08:30 → 09:10):** GMT 일봉은 09:00 KST(00:00 UTC)에 마감된다. 08:30에는 직전 거래일 일봉이 아직 미완성이라, 완성본을 안정적으로 받기 위해 09:10로 조정했다.

## 2. 배경 및 문제 정의 (Background & Problem)

- 환율은 자금·정산·해외거래·가격정책 의사결정에 매일 영향을 주는 핵심 지표다.
- 현재는 담당자가 매일 아침 직접 확인·정리·공유한다 → 반복 수작업, 일관성 부족, 이력 관리 부재.
- 공식 스냅샷 값만으로는 **장중 변동폭(고가·저가)** 파악이 어려워, 시장 일봉 **OHLC**가 필요하다.

## 3. 목표 (Goals) / 비목표 (Non-Goals)

### 3.1 목표
- G1. **영업일 매일 09:10 KST**에 사람 개입 없이 환율 보고서를 자동 생성·발송한다.
- G2. USD·JPY의 **일봉 OHLC + 전일 대비 등락**을 한눈에 제공한다.
- G3. **Investing.com 일봉과 시간대(GMT)를 정합**하여 대조·검증이 쉽게 한다.
- G4. Notion에 **일자별 시계열로 축적**하여 이력·추세 조회가 가능하게 한다.
- G5. 조회/기록 실패 시 **Slackbot 알림**으로 즉시 인지하게 한다.

### 3.2 비목표
- N1. 환율 예측/전망 분석.  N2. 실시간/틱 스트리밍(1일 1회 스냅샷).
- N3. 매매·헤지 등 트랜잭션 실행.  N4. USD·JPY 외 통화(추후 확장).

## 5. 핵심 요구사항 (Requirements)

### 5.1 데이터 수집 (Twelve Data 단일 소스)
- R1. **영업일** 09:10(KST)에 최신 일봉을 조회한다.
- R2. 기준 통화 **KRW**, 대상 심볼 **`USD/KRW`, `JPY/KRW`** *(확정)*.
- R3. **Twelve Data `time_series` (endpoint), `interval=1day`, `timezone=UTC`** *(확정)*.
  - **`timezone=UTC`**로 GMT 일봉 경계를 Investing.com과 정합한다. 응답 `meta.exchange_timezone`이 `UTC`인지 검증한다.
  - `outputsize`는 최소 3~5로 조회하여 **완성된 직전 거래일 일봉**과 **그 이전 거래일 일봉**을 확보한다(등락 계산용).
- R4. **거래일 처리:** Twelve Data는 FX 거래일 캔들만 반환하므로, 응답에서 **가장 최근 완성 일봉(직전 거래일)** 과 **직전전 거래일**을 사용한다(주말·비거래일은 자연히 제외됨). 08:30이 아닌 09:10 발송으로 직전 거래일 일봉의 완성을 보장한다.
- R5. **JPY 단위 정합:** `JPY/KRW`는 **1엔 기준** → 보고서·DB는 **100엔 기준으로 ×100 환산**하여 표기한다.
- R6. 각 심볼별 파생값 계산.
  - 일봉 **시가/고가/저가/종가(OHLC)**
  - **전일 대비 등락액/등락률(%)** = 직전 거래일 종가 − 직전전 거래일 종가.
- R7. 응답 결측/지연 시 재시도(§5.5) 및 부분 데이터 허용(결측 `N/A` 표기).

### 5.2 보고서 생성
- R8. 보고서 구성.
  - 헤더: `📈 환율 보고서 | 발송 YYYY-MM-DD(요일) 09:10 KST`
  - 기준 표기: `기준: YYYY-MM-DD (GMT 일봉, 직전 거래일) · 출처: Twelve Data`
  - 심볼별: `국기 심볼 : 종가 (▲/▼ 등락액, 등락률%)` + `OHLC(시/고/저/종)`
  - 등락 방향 시각 표기(▲ 상승 / ▼ 하락 / - 보합)
- R9. 숫자는 천 단위 구분, 소수 2자리 통일. JPY는 100엔 기준.

### 5.3 Notion 기록
- R10. **대상 Notion 위치(확정):** 페이지 `https://app.notion.com/p/3b4ecd34b1c780ef920ff9190533edec` (page id `3b4ecd34b1c780ef920ff9190533edec`).
  - 해당 페이지 하위에 **시계열 데이터베이스(DB)**를 생성/사용하고, 매 영업일 심볼별 행을 추가한다.
- R11. **DB 스키마(권장):**
  | 컬럼 | 타입 | 설명 |
  |------|------|------|
  | 기준일 | Date | GMT 일봉 기준 거래일 |
  | 통화 | Select | USD/KRW · JPY/KRW(100엔) |
  | 시가/고가/저가/종가 | Number×4 | Twelve Data 일봉 OHLC(GMT) |
  | 전일대비 | Number | 종가 등락액 |
  | 등락률(%) | Number | 종가 등락률 |
  | 출처 | Text | Twelve Data |
  | 발송시각 | Created time | 자동 |
- R12. 가독형 요약(§7 목업)은 페이지 콘텐츠(콜아웃/표 블록)로도 함께 남긴다.
- R13. 기록 성공/실패를 로그로 남긴다.

### 5.4 스케줄링
- R14. **영업일 매일 09:10 KST** 자동 실행 (= **00:10 UTC**, 크론은 UTC 기준으로 등록).
- R15. **영업일만 발송** *(확정)*: 토·일 미발송 + **공휴일 미발송**.
- R16. **공휴일 판정: 공공데이터포털 특일정보 API 연동** *(확정)* — 실행일(KST)이 공휴일이면 스킵(미발송).

### 5.5 오류 처리 · 알림 (Slackbot)
- R17. Twelve Data 조회 실패 시 재시도(2회, 지수 백오프). 최종 실패 시 **Slackbot 실패 알림**("환율 조회 실패 — 수동 확인 필요", 사유 포함).
- R18. 부분 실패(일부 심볼만 조회) 시, 확보 데이터는 Notion 기록 + 결측 `N/A` 표기 + Slackbot 경고.
- R19. Notion 기록 실패 시에도 **Slackbot 알림**으로 통지한다.

## 8. 데이터 소스 (Data Sources) — 확정

| 소스 | 용도 | 특징 / 유의 |
|------|------|-------------|
| **Twelve Data REST API** | 일봉 OHLC (USD/KRW, JPY/KRW) | 무료 티어(예: **8 req/min, 800 credits/day**), API Key 필요. `timezone=UTC`로 GMT 정합. JPY 1엔→100엔 환산 필요 |
| **공공데이터포털 특일정보 API** | 공휴일 판정 | 실행일(KST) 공휴일 여부 확인 → 미발송 처리 |

### 8.1 시간대 정합 검증 결과 (중요)
- Twelve Data **Forex 기본 시간대는 `America/New_York`(UTC-4/-5)**, Investing.com 일봉(Overview) 기본은 **GMT(UTC+0)** → **기본값 그대로면 일봉 경계가 4~5시간 어긋나 값이 불일치**.
- **정합 방법:** Twelve Data 요청에 **`timezone=UTC`** 지정 → Investing GMT 일봉과 경계 정렬.
- **시간대는 API 키의 속성이 아니라 요청 파라미터 + `meta.exchange_timezone` 값**이다(키와 무관하게 요청에서 제어).
- ⚠️ **caveat:** FX는 통합 시세가 없어 시간대를 맞춰도 공급자 간 OHLC가 **소수점 단위로 다를 수 있음**(경계 정합까지만 보장). 완전 동일값이 필요하면 Investing 자체 피드가 필요.
- **검증 커맨드(키 보유 환경):**
  ```bash
  curl "https://api.twelvedata.com/time_series?symbol=USD/KRW&interval=1day&outputsize=3&timezone=UTC&apikey=YOUR_KEY"
  # meta.exchange_timezone == "UTC", datetime == GMT 자정 기준 확인
  ```

## 9. 시스템 아키텍처 — 옵션 A (Claude Code Routine) 확정

```
[Claude Routine  (영업일 09:10 KST = 00:10 UTC 트리거)]
        │
        ▼
[영업일/공휴일 판정]  ── (특일정보 API) 휴일이면 종료(미발송)
        │  (영업일)
        ▼
[Twelve Data API 호출]   time_series · interval=1day · timezone=UTC
        │  (직전/직전전 거래일 완성 일봉)  ──실패 시 재시도
        ▼
[보고서 생성]  (JPY ×100 환산 · 등락 계산 · OHLC 포맷팅)
        │
        ▼
[Notion 기록]  (DB 행 추가 + 요약 블록)
        │
    성공 ───┴─── 실패 / 부분실패
                    │
                    ▼
          [Slackbot 실패·경고 알림]
```

- **트리거:** Claude Code 스케줄 트리거(Routine) — 영업일 **00:10 UTC(= 09:10 KST)**. 주말 제외는 크론, 공휴일은 세션 로직(특일정보).
- **연동:** Twelve Data·특일정보 API(HTTPS), Notion MCP(기록), Slack(Slackbot 알림).
- 장점: 별도 서버/인프라 불필요.  유의: 트리거 신뢰성·API Key/토큰 유지, 실행 로그 확인.

## 13. 리스크 (Risks)

- 시간대 미정합(기본 NY) → **`timezone=UTC` 강제** 및 `meta.exchange_timezone` 검증으로 방지.
- 발송 시각·일봉 완성 충돌 → **09:10 KST(00:00 UTC 마감 이후)** 발송으로 완성본 확보.
- 공급자 간 OHLC 미세 차이(FX 통합시세 부재) → "경계 정합" 한계 명시, 필요 시 소스 재검토.
- Twelve Data 무료 한도 초과 → 호출 최소화(2심볼/일), 한도 모니터링.
- JPY 단위 불일치(1엔↔100엔) → 환산 로직 검증(테스트 케이스 고정).
- 크론 UTC↔KST 변환/요일 시프트 오류 → 트리거 검증 및 첫 주 모니터링.
- 공휴일 판정 누락 → 특일정보 API 실패 시 폴백(수기 목록) 및 알림.
- Notion/Slack 토큰 만료, 실행 환경 `api.twelvedata.com` 차단 → 실패 감지·알림 및 네트워크 사전 확인.
