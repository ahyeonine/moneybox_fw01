## 1. 개요 (Overview)

**영업일 매일 아침 08:30(KST)**에 주요 통화(**USD, JPY**)의 환율 정보를 수집하여, 사람이 읽기 좋은 **환율 보고서**를 생성하고 지정된 **Notion**에 자동 기록/발송하는 시스템.

- **공식 기준율**은 한국수출입은행 매매기준율에서,
- **장중 시장 OHLC(시/고/저/종)**는 Twelve Data에서 가져와 함께 제공한다.
- 일자별 환율을 Notion에 **시계열로 축적**하고, 조회·기록 실패 시 **Slackbot으로 알림**한다.

---

## 2. 배경 및 문제 정의 (Background & Problem)

- 환율은 자금·정산·해외거래·가격정책 의사결정에 매일 영향을 주는 핵심 지표다.
- 현재는 담당자가 매일 아침 직접 확인·정리·공유한다 → 반복 수작업, 일관성 부족, 이력 관리 부재.
- 특히 공식 기준율만으로는 **장중 변동폭(고가·저가)** 파악이 어려워 OHLC 보강이 필요하다.

---

## 3. 목표 (Goals) / 비목표 (Non-Goals)

### 3.1 목표
- G1. **영업일 매일 08:30 KST**에 사람 개입 없이 환율 보고서를 자동 생성·발송한다.
- G2. USD·JPY의 **공식 기준율 + 장중 OHLC + 전일 대비 등락**을 한눈에 제공한다.
- G3. Notion에 **일자별 시계열로 축적**하여 이력·추세 조회가 가능하게 한다.
- G4. 조회/기록 실패 시 **Slackbot 알림**으로 즉시 인지하게 한다.

### 3.2 비목표
- N1. 환율 예측/전망 분석.  N2. 실시간/틱 스트리밍(1일 1회 스냅샷).
- N3. 매매·헤지 등 트랜잭션 실행.  N4. USD·JPY 외 통화(추후 확장).

## 5. 핵심 요구사항 (Requirements)

### 5.1 데이터 수집 (이원 소스)
- R1. **영업일** 08:30(KST)에 최신 환율을 조회한다.
- R2. 기준 통화 **KRW**, 대상 통화 **USD, JPY(100엔)** *(확정)*.
- R3. **소스 ① 한국수출입은행 매매기준율 API** — 공식 일별 기준율(`deal_bas_r`).
  - 조회 항목: 매매기준율, (제공 시) 전신환 매도/매입율.
- R4. **소스 ② Twelve Data REST API** — 장중 시장 **일봉 OHLC**.
  - 심볼: `USD/KRW`, `JPY/KRW` (endpoint: `time_series`, `interval=1day`).
  - 08:30 시점에는 당일 일봉이 미완성이므로 **직전 거래일의 완성된 일봉 OHLC**를 사용한다.
  - ⚠️ **JPY 단위 정합**: Twelve Data `JPY/KRW`는 1엔 기준 → 보고서는 **100엔 기준**으로 환산(×100)하여 한국수출입은행 표기와 통일한다.
- R5. 각 통화별 파생값 계산: 당일 기준율, 전일(직전 영업일) 기준율, **전일 대비 등락액/등락률(%)**.
- R6. 특정 소스 미갱신/누락 시 직전 영업일 값 사용 및 그 사실을 표기(부분 데이터 허용).

### 5.2 보고서 생성
- R7. 보고서 구성.
  - 헤더: `📈 환율 보고서 | YYYY-MM-DD (요일) 08:30 KST 기준`
  - 통화별: `국기 통화 : 기준율 (▲/▼ 등락액, 등락률%)` + `장중 OHLC(시/고/저/종)`
  - 등락 방향 시각 표기(▲ 상승 / ▼ 하락 / - 보합)
  - 출처(한국수출입은행 · Twelve Data) 및 기준일 명시.
- R8. 숫자는 천 단위 구분, 소수 2자리 통일. JPY는 100엔 기준.

### 5.3 Notion 기록
- R9. **대상 Notion 위치(확정):** 페이지 `https://app.notion.com/p/3b4ecd34b1c780ef920ff9190533edec` (page id `3b4ecd34b1c780ef920ff9190533edec`).
  - 해당 페이지 하위에 **시계열 데이터베이스(DB)**를 생성/사용하고, 매 영업일 행을 추가한다.
- R10. **DB 스키마(권장):**
  | 컬럼 | 타입 | 설명 |
  |------|------|------|
  | 기준일 | Date | 데이터 기준 영업일 |
  | 통화 | Select | USD / JPY(100엔) |
  | 기준율 | Number | 한국수출입은행 매매기준율 |
  | 시가/고가/저가/종가 | Number×4 | Twelve Data 일봉 OHLC |
  | 전일대비 | Number | 등락액 |
  | 등락률(%) | Number | 등락률 |
  | 출처 | Text | 한국수출입은행·Twelve Data |
  | 기록시각 | Created time | 자동 |
- R11. 가독형 요약(§7 목업)은 페이지 콘텐츠(콜아웃/표 블록)로도 함께 남긴다.
- R12. 기록 성공/실패를 로그로 남긴다.

### 5.4 스케줄링
- R13. **영업일 매일 08:30 KST** 자동 실행.
- R14. **영업일만 발송** *(확정)*: 토·일 미발송 + **공휴일 미발송**.
- R15. **공휴일 판정: 공공데이터포털 특일정보 API 연동** *(확정)* — 실행일이 공휴일이면 스킵(미발송).

### 5.5 오류 처리 · 알림 (Slackbot)
- R16. 데이터 조회 실패 시 재시도(2회, 지수 백오프). 최종 실패 시 **Slackbot으로 실패 알림** 발송("환율 조회 실패 — 수동 확인 필요", 실패 소스/사유 포함).
- R17. 부분 실패(일부 소스/통화만 조회) 시, 확보된 데이터는 Notion에 기록하고 결측은 `N/A` 표기 + Slackbot 경고.
- R18. Notion 기록 실패 시에도 **Slackbot 알림**으로 통지한다.

## 6. 사용자 시나리오 (User Scenario)

> **평일 아침 08:30**, Notion `환율 보고` DB에 오늘자 USD·JPY 행이 자동 추가된다.
> 담당자 A는 USD 1,372.50원(▲4.20, +0.31%)과 장중 고가/저가까지 한 번에 확인한다.

## 8. 데이터 소스 (Data Sources) — 확정

| 소스 | 용도 | 특징 / 유의 |
|------|------|-------------|
| **한국수출입은행 현재환율 API** | 공식 매매기준율 | 무료·국내 공신력, API Key 필요, 영업일 1회성 일별값(주말·공휴일 미갱신) |
| **Twelve Data REST API** | 장중 일봉 OHLC | 무료 티어(예: **8 req/min, 800 credits/day**), API Key 필요, `USD/KRW`·`JPY/KRW`(JPY 1엔→100엔 환산) |
| **공공데이터포털 특일정보 API** | 공휴일 판정 | 실행일 공휴일 여부 확인 → 미발송 처리 |

> Twelve Data 무료 티어 rate limit은 하루 2심볼 조회에 충분하나, 재시도·확장 시 한도 관리 필요.

## 9. 시스템 아키텍처 — 옵션 A (Claude Code Routine) 확정

```
[Claude Routine  (영업일 08:30 KST 트리거)]
        │
        ▼
[영업일/공휴일 판정]  ── (특일정보 API) 휴일이면 종료(미발송)
        │  (영업일)
        ├────────────────────────────┐
        ▼                            ▼
[한국수출입은행 API]           [Twelve Data API]
  공식 매매기준율                장중 일봉 OHLC
        └───────────┬────────────────┘
                    ▼
        [보고서 생성]  (등락 계산 · OHLC 병합 · 포맷팅)
                    │
                    ▼
        [Notion 기록]  (DB 행 추가 + 요약 블록)
                    │
            성공 ───┴─── 실패 / 부분실패
                            │
                            ▼
                  [Slackbot 실패·경고 알림]
```

- **트리거:** Claude Code 스케줄 트리거(Routine) — 영업일 08:30 KST.
  - 크론은 UTC 기준: **08:30 KST = 23:30 UTC(전일)**. 요일 시프트 유의(주말 제외는 크론, 공휴일은 세션 로직).
- **연동:** 한국수출입은행·Twelve Data·특일정보 API(HTTPS), Notion MCP(기록), Slack(Slackbot 알림).
- 장점: 별도 서버/인프라 불필요.  유의: 트리거 신뢰성·API Key/토큰 유지, 실행 로그 확인.

## 13. 리스크 (Risks)

- API 갱신 지연/장애 → 재시도 + 직전 영업일 폴백 + Slackbot 알림.
- Twelve Data 무료 한도 초과 → 호출 최소화(2심볼/일), 한도 모니터링.
- JPY 단위 불일치(1엔↔100엔) → 환산 로직 검증(테스트 케이스 고정).
- 크론 UTC↔KST 변환/요일 시프트 오류 → 트리거 검증 및 첫 주 모니터링.
- 공휴일 판정 누락 → 특일정보 API 실패 시 폴백(수기 목록) 및 알림.
- Notion/Slack 토큰 만료 → 실패 감지·알림.
